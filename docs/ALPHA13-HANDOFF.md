## Цель пользователя и выбранный путь

Продолжить Android Fly Connectome Emulator после исчерпания контекста предыдущего агента. Последняя задача — сделать обучение понятным: показ человеком в realtime либо Automode, затем обучение FDB; сохранить исследовательские настройки. Сообщение о «зависании» относится к остановке диалога; новая ошибка приложения этим сообщением не подтверждена.

Alpha12 уже содержала отдельные веса подражания и SARSA, управляемое обучение FDB, непрерывную игру, замороженную проверку и четыре эмулируемые платформы. Alpha13 развивает первичные данные и архив сессий. Подробности и ограничения — [TRAINING.md](TRAINING.md).

## Что реализовано

- `human-capture.js`: события состояния ввода отделены от реально исполненных действий. Тап между кадрами остаётся событием ввода без выдуманной обучающей метки. Нажатие на один кадр получает фактическую длительность. Наблюдение фиксируется до действия, образец принимается после успешного `frame()`. Удержания собираются около 0.1 секунды игрового времени и закрываются при смене кнопок/остановке.
- `training-sessions.js`: Store/Writer, UUID, последовательности пакетов, native RPC и резервный localStorage. Begin/append/close отправляются сразу в порядке, без ожидания WebView callbacks. Очередь ограничена; завершённые promises удаляются.
- `TrainingSessionStore.java`: приватный append-only `events.jsonl`; fsync данных перед атомарным `meta.json`. Метаданные закрепляют префикс файла и хеш последнего пакета. Повтор последнего пакета идемпотентен; пропущенные/переставленные события отклоняются. Неподтверждённый хвост не экспортируется и усекается перед следующим append.
- `training-journal.js`: production frame/input hooks, сохранение сессий, принятые/пропущенные действия, игровое время и удержания кнопок. Пауза, уход из игрового экрана, потеря фокуса, смена режима и перезапуск закрывают сессию. Можно просмотреть другие ROM/графы, экспортировать полный архив и удалить выбранный после подтверждения; веса сохраняются.
- Экспорт Android NDJSON потоковый: заголовок `fly-human-session-jsonl` v1 и затем отдельные события. Полный архив не проходит через ограниченный экспорт модели.
- Режим benchmark явно выбирает `eval`; активный benchmark также исключён из записи показа. Проверена оценка после режима «Показываю сам», включая открытый игровой экран: веса и архив не меняются.

## Инварианты

В обычном single-player P1 находится в `appliedMask/appliedAgentMask`, а `appliedHumanMask` равен нулю. Capture использует фактически применённый P1; нейронные кнопки исключены во время показа.

Архив содержит `input` и `sample`: номер события/кадра, настенное и относительное время, игровое время и маску. Sample добавляет признаки/ретину до действия, текущие выходы сети, количество кадров, длительность, конечный кадр и результат принятия. Это игровое состояние кнопок после нормализации противоположных направлений, а не журнал физических скан-кодов.

Модель и live FDB сохраняют последние 200 принятых примеров; FDB получает пакеты до 16. Полный архив пока не подключён к повторному обучению. Длительность сохраняется для анализа и не масштабирует градиент подражания.

Метаданные сессии привязаны к platform/ROM SHA256/graph SHA256. Они содержат профиль/настройки и количество FDB edges/deltas; полный FDB, ROM, базовый граф и LIF state в архив не входят. Для весов/FDB/старта используется модель или Layer Set.

Android: 32 МиБ/сессию, 64 МиБ событий всего, 32 сессии. Browser fallback: 2 МиБ/сессию, 32 сессии плюс квота localStorage. Заполнение/ошибка записи не удаляет историю; онлайн-подражание продолжает работу, дальнейшая запись останавливается с сообщением. Буфер отправляется каждую секунду, при 32 событиях и при остановке; авария процесса может потерять неотправленные данные.

Policy v1/v2/v3 и прежние model/Layer Set пакеты сохранены. Исходный коннектом не изменяется; FDB остаётся экспериментальным синтетическим слоем. Длительность кнопок показывает состав опыта, а не качество игры.

## Проверки и важные исправления

Новые unit tests: `human_capture_check.cjs`, `training_sessions_check.cjs`, `TrainingSessionStoreCheck.java`. Проверены короткие тапы, дробная частота SNES, pre-action наблюдения, история длиннее 200, сохранность префикса при ошибке, quota rollback, FIFO при уходе WebView в фон, строгая валидация, пределы и удаление только выбранного архива.

`training_ui_check.cjs` проверяет настоящие NES/SNES WASM/UI, владение P1, sub-frame и one-frame ввод, persistence/обзор, bounded FDB, замороженную оценку, manual reward exclusion, архив других платформ, отмену/подтверждение удаления без сброса весов и benchmark после показа.

Журнал заметок свёрнут по умолчанию; `layer_ui_check.cjs` теперь открывает его summary перед вводом. Все четыре browser suites запускаются независимо, ошибки агрегируются. Это исправило первую неудачную сборку.

## Воспроизведение выпуска

1. Восстановить доступ к рабочей среде. Не регенерировать signing key.
2. Синхронизировать исходники с проверенным source commit выше. Локальная старая копия может ещё не содержать benchmark fix, сделанный через GitHub после отключения среды.
3. Забрать artifacts **CI 37800999099**: `FlyConsole-apk-part-1/2/3` и `FlyConsole-ui-preview`. Проверить SHA256 каждого artifact ZIP, целостность ZIP и склеить raw APK parts по порядку. Не использовать artifacts предыдущего CI 37797707260 как финальный исходник.
4. Подписать существующим release PKCS12 и официальным `apksigner.jar`. Использовать `--ks-pass file:...`; отдельный `--key-pass` не нужен. v4 отключить. Приватный ключ/пароль не печатать и не коммитить; использовать прежнюю приватную резервную копию при утрате временной среды.
5. Проверить package/versionCode/versionName, v2/v3 подписи и совпадение сертификата с alpha10–alpha12. Ожидаемый публичный cert SHA256: `28b4e8456b81ae991c07d4618a9d8fd92a04d35651ed76b2acf1da0334327500`. Проверить manifest, source/licence/WASM хеши и точное совпадение новых lab assets с исходником.
6. Сохранить и выдать подписанный `FlyConsole-2.0.0-alpha13.apk`, результат верификации и актуальную точку продолжения. Не публиковать временные download URLs или приватный signing material.

Прежние временные helper scripts назывались `download_a13_artifacts.py` и `verify_a13.py`; их можно восстановить. Java compiler в прежней среде работал через `java com.sun.tools.javac.Main`, хотя launcher javac отсутствовал.
