# AGOD PR2: ограниченная трассировка NES

База: `134ed71c96e09bdcc09734903fccdd252b8dc856`, ветка
`feature/agod-instrumented-nes`. Предыдущий этап прошёл все 45 шагов
[Actions](https://github.com/terminaldetector/Gu/actions/runs/40005767279),
включая общий host check и все 23 браузерных набора.
ТЗ: [AGOD v1.2](GU_AUTOMATIC_GAME_OBJECTIVE_DISCOVERY_TZ_v1_2.md).

Этот этап устанавливает происхождение **записей эмулятора** в NES RAM.
Он не определяет полезность события, победу, поражение или знак награды.
Полярность и reward остаются `UNKNOWN`; FDB, learned checkpoints и Best gate
не получают новые входы из CPU trace.

## Исходники и обычная эмуляция

Инструментированный helper воспроизводимо собирается из закреплённого
исходного CPU JSNES 2.1.0. Опубликованный upstream bundle должен совпадать
с используемым `jsnes.min.js`; minified vendor вручную не патчится.
Проверка сборки выполняется offline из сохранённого исходника и manifest.

Helper временно подменяет методы только одного CPU instance. После окончания
окна восстанавливаются прежние методы; обычная эмуляция исполняет прежний путь.
Загруженная игра не пересоздаётся, её Save State и learned state не откатываются.
Ошибки получателя трассы не должны превращаться в ошибки игрового ядра.

Writer PC фиксируется у реально исполняемой инструкции, после обработки
предшествующего interrupt. Внешние записи и interrupt stack без однозначной
инструкции получают неизвестное происхождение, а не предыдущий PC.
RAM-зеркала канонизируются к 2 KiB; I/O, PPU/APU и mapper-регистры не читаются
как игровые переменные. Старое значение считывается только из обычной RAM.

## Точность и ограничение платформы

Для NROM-128/256 можно установить статическое соответствие PC → PRG bank/offset.
При неподдержанном mapper, выполнении из RAM или неоднозначном соответствии
bank/offset остаётся неизвестным. Поддержка банкового переключения не выводится
из наличия логического PC.

В этом адаптере не доказано соответствие внутренних счётчиков JSNES абсолютной
фазе аппаратной записи на шине. Поэтому поле cycle не подменяется номером
инструкции: оно остаётся `null` с явным неизвестным статусом. Нормализация и
проверка cycle timestamp остаются отдельным ограничением. Трасса отражает
фактические операции JSNES, включая реализованные им dummy writes; она не
заявляется независимо проверенной cycle-accurate 6502 hardware bus trace.

## Ресурсы и интерфейс

Сохраняется один глобальный экспериментальный gate в лаборатории, default OFF.
Новых задач, RAM-адресов и ручной разметки для каждого ROM нет. Короткое
диагностическое окно выбирает watchpoints из обычных RAM-кандидатов.
Смена контекста, pause/background, оценка, ручное вмешательство и ошибка
отменяют окно. Лимиты кадров, событий и wall time действуют независимо.

Сырые события существуют только в ограниченной локальной очереди адаптера.
Обычный отчёт и постоянный logger получают счётчики, покрытие и причину
завершения; значения памяти и полный поток CPU не экспортируются по умолчанию.
Стоимость установки и активного окна учитывается отдельно от RAM miner.

Превышение лимита прекращает трассу и делает покрытие неполным; это не
игровая ошибка и не награда. Вне окна hook снят. Доказательство стоимости
на телефоне и включение default-on остаются gate S3.

## Приёмка

Результаты actual-CPU parity, известные writer sites/banks, отрицательные
примеры, парные host timing и общая регрессия публикуются отдельно в
[отчёте PR2](reports/agod-instrumented-nes-2026-10-24/README.md).
Ни семь вариантов первого генератора, ни новый тестовый ROM не заменяют
независимую проверку реальных игровых целей.

Следующие этапы: PR3 — причинность, происхождение независимых групп и полярность;
PR4 — verified reward bridge с исполненным credit window и idempotency;
PR5 — Android, frozen behavior и ограниченное пользовательское включение.
Автоматическое слияние в `main` не выполняется.
