## Ключевые факты, установленные измерением (не из документов)

1. База ТЗ подтверждена посимвольно; worktree чист.
2. Всё, что запускается в этом окружении, проходит: 115 PASS-утверждений в `check.sh` + 10 шагов после блокера + 5 AGOD-проверок.
3. Ровно 3 шага недоступны, все по одной причине — отсутствие emscripten для SNES/GB-ядер.
4. ТЗ §2.1 воспроизведён точно (7/7 структурных, 1/7 точный типизированный счётчик).
5. ТЗ §2.2 воспроизведён по паритету (32 / 25 / 117), **но не по overhead** — разброс между прогонами 1.285×–1.526×.
6. Разрыв §2.4 подтверждён данными: 0 verified rewards, 0 independent confirmations, polarity unknown на всех 7 ROM.
7. Все 4 внешних SHA из ТЗ существуют, но **2 из 4 путей, подразумеваемых ТЗ, на этих коммитах не существуют** (rcheevos: `src/runtime/rc_*.c`; stable-retro: пакет переименован в `stable_retro/`).
8. Все 4 проекта под MIT — лицензионных препятствий нет.
9. **SB3 `DQN.train` — ванильный DQN, не Double DQN**, которого требует NN-01: цель Double DQN придётся писать самим.
10. Награда в Stable-Retro задаётся рукописным сценарием на каждую игру → для пути обнаружения не годится, но годится в независимые оракулы §11.2.
11. ADOPT NOW: ноль механизмов. Три PROTOTYPE, один REJECT для пути обнаружения.
12. **Наивное сравнение «действие против нейтрали» систематически ложно**: нажатие кнопки сдвигает фазу времязависимых счётчиков (reset на 12 кадрах = нейтраль на 11). На 7 картриджах это дало бы 101 ложную причинную привязку.
13. С контролем сдвига причинный движок восстанавливает истинные связи действие→эффект: 7/7 по счёту, жизням и меню, все 8 кнопок по эху ввода, 0 привязок декоев, 0 эффектов у непривязанных кнопок.
14. **Полярность асимметрична**: `NEGATIVE` доказуема изнутри эмулятора (исчерпание ресурса + потеря подтверждённых эффектов) — 7/7; `POSITIVE` недоказуема и заблокирована по построению — 0/7. Для положительной награды нужен внешний источник истины.
15. Брокер награды: 17/17 негативных кейсов (включая все 8 из §6.3), контракт `UNKNOWN` переживает JSON round-trip без превращения в 0.
16. **Цель, выведенная из картриджа, доходит до `VERIFIED` без фикстуры**: 7/7 на трёх независимо прогнанных разделах (0 пересечений по ключам стартов), после чего брокер выдаёт `value = −1`. Реестр не стал обходным путём к `POSITIVE`: 0/7 накопителей подтверждены при полном комплекте доказательств.
17. **Тип игровой переменной определяется, а не перечисляется**: 7/7 по активному span, 6/7 с полной объявленной шириной, против «точный тип присутствует в списке» 1/7 и `fullTypeIdentified` = константа `false` в базе. Знаковость не заявляется ни разу (модульные шаги беззнакового и дополнительного кодов совпадают), кодировка жизней остаётся неразличимой 0/7 — и это верный ответ.
18. **Нейтральный прогон той же длины стоит 55 ложных типизаций**: без него тот же идентификатор объявляет игровыми переменными 55 времязависимых декоев (обычно один байт привязывается ко всем восьми кнопкам), с ним — 0.
19. **Агент учится только тогда, когда цепочка выдала подтверждённую награду**: 0 обновлений весов и 0 выплат в контроле с неподтверждённой целью, против 111–238 обновлений и 70–84 выплат при `VERIFIED`. `UNKNOWN` не кладётся в replay вообще — это отсутствие доказательства, а не награда 0.
20. **Выучивается избегание и ничего больше**: среди двух неоштрафованных действий обученные агенты распределились 21/21, потому что за рост счёта награды нет. Прямое следствие асимметрии полярности из E4.
21. **Конвейер собран в один вызов и проверен на невиданных картриджах**: held-out-семена 200…206, зафиксированные до первого прогона, дали 7/7 `VERIFIED` без единой подстройки — семь независимых обнаружений со своими масками, адресами и кодировками. Агент, обучавшийся только на подтверждённой этим конвейером награде: 0.000 выборов штрафуемого действия, Q(стоимость) минимум в 21/21.
22. **Собственная проверка поймала пустой ноль**: первый прогон агентной части показал идеальные 0.000 при нуле выплат и нуле обновлений, потому что конвейер отдаёт машину с исчерпанным ресурсом. Утверждение `runsWithoutWeightUpdates === 0` это отловило; добавлено `paidClaims > 0` на каждый прогон.
23. Идентичность старта выводится из ROM, ядра, родительского состояния и пути восстановления: **новый идентификатор не создаёт нового доказательства** (проверено), а подменённый holdout из стартов discovery не повышает гипотезу — 0/7.
