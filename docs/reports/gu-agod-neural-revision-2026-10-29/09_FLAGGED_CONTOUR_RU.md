# S1 — Экспериментальный контур внутри GU за feature flag

Решение Sol, приоритет 1 милстоуна: «перенос уже созданных экспериментальных
модулей в исполняемый контур GU за feature flags».

Статус: **сделано и измерено.** Модули достижимы из работающей лаборатории; при
выключенном флаге страница ведёт себя так, как если бы файла моста не существовало.

- Модуль: `app/src/main/assets/lab/agod-experimental.js` (новый)
- Изменён ровно один существующий файл: `app/src/main/assets/lab/index.html` — **одна
  строка**, один тег `<script>`
- Проверка: `tools/agod_experimental_bridge_check.cjs`
- Данные: `logs/bridge_report.json`, лог `logs/agod_experimental_bridge_check.log`

## 1. Почему мост грузит модули лениво

Семь стадий не перечислены в `index.html`. Их загружает мост, и только после
включения флага. Причина прямая: пока флаг выключен, продакшен-контур не должен
платить ничего — ни запроса, ни парсинга, ни регистрации глобалей. Поэтому в
`index.html` добавлен один инертный скрипт, а не восемь.

Флаг: `gu-agod-neural-experimental-v1`, по умолчанию **выключен**, хранится в
`localStorage` (тот же механизм, что у существующего `gu-agod-experimental-v1`).

При выключенном флаге **каждая** точка входа возвращает названный отказ
(`status:'DISABLED'`), а не тишину и не пустой результат.

## 2. «Ничего не меняется при выключенном флаге» — проверено, а не обещано

Проверка поднимает продакшен-страницу в headless Chromium **дважды**: как она
поставляется и с вырезанным тегом моста, — и сравнивает оба прогона.

| Наблюдение | Без моста | С мостом (флаг выключен) |
|---|---|---|
| ошибки страницы | 0 | **0** (множества совпадают) |
| точки входа продакшена (`labLoadRom`, `labConfigured`, `labResult`, `labError`, `labPause`) | 5 | **5**, те же |
| исследовательские глобали | 0 | **0** — ни одна стадия не загружена |
| детей в панели `trainingResearch` | 14 | **14** — мост не добавляет элементов |

Страница доводится до состояния реального сеанса (загружен диагностический
картридж, `loaded === true`), а не до пустого DOMContentLoaded.

## 3. При включении

| Наблюдение | Результат |
|---|---|
| `ready()` | `READY`, 7/7 стадий зарегистрированы |
| ревизии | `agod-pipeline-e6-1`, `agod-dqn-e5-1` |
| `session(null)` | `REFUSED` — «driver must provide restore, run, readRam, snapshot and stateHash», то есть конвейер действительно подключён, а не заглушён |
| точки входа продакшена после включения | не изменились |
| ошибки страницы после включения | 0 |
| флаг переживает сеанс | да (`localStorage` = `true`) |
| выключение обратно | точки входа снова отказывают (`DISABLED`) |

Выгрузить уже загруженный код нельзя, поэтому после выключения глобали остаются —
но ни одна точка входа больше не работает. Это заявлено явно, а не скрыто.

## 4. Чего S1 НЕ сделал

1. **Пользовательского переключателя нет, намеренно.** Панель
   `trainingResearch` проверяется существующими UI-тестами, и добавление в неё
   элемента — продуктовое решение, а не исследовательское. Флаг включается через
   `FlyAgodExperimental.setEnabled(true)` или `localStorage`.
2. **Прерываемости и сохранения промежуточного состояния исследования пока нет**
   (решение Sol 3 требует их для исследовательского сеанса) — это следующий слой.
3. **Отдельного performance budget для активного исследования нет**: мост ничего не
   измеряет и ничего не ограничивает по времени и памяти.
4. На Android мост не запускался: устройства нет, конфигурацию сборки не трогал.

## 5. Регрессия существующего UI

Запрещённые к изменению файлы не затронуты. Из UI-проверок, которым не нужен
Java-фикстура, прогнаны пять:

| Проверка | Результат |
|---|---|
| `console_layout_check` | PASS |
| `goal_discovery_ui_check` | PASS |
| `agent_quick_panel_ui_check` | PASS |
| `console_navigation_ui_check` | PASS |
| `action_hold_ui_check` | **FAIL — и так же падает без моего изменения** |

`action_hold_ui_check` перебирает `['nes','sega','snes','gb']`, а ядра SNES и GB в
этом окружении собрать нечем (ограничение A1, нет emscripten). Проверено прямым
контролем: с вырезанным тегом моста проверка падает тем же таймаутом на той же
строке. Это предсуществующий блокер окружения, а не следствие S1.
