# Архитектурный план: перенос AGOD на NES, Mega Drive, GB/GBC и SNES

Это **план, а не реализация**. Указание Sol: зафиксировать архитектуру переноса через
платформенные адаптеры и **не начинать** сейчас переписывание эмуляторов. Ни одна
строка production не менялась, ни одно ядро не переписывалось.

Граница, объявленная Sol:

```
Emulator Core → Platform Observation/Action Adapter → AGOD/FDB → Verified Reward → Learning
```

## 1. Что уже выполняется, проверено по исходникам

Факт, который меняет оценку объёма работ: **все четыре ядра уже предоставляют один и
тот же набор примитивов**, который нужен драйверу AGOD. Это не вывод из документации,
а чтение кода.

| примитив | NES (`jsnes.min.js`) | Mega Drive (`sega-core.js`) | GB/GBC и SNES (`retro-core.js`) |
|---|---|---|---|
| чтение RAM | `cpu.mem` (массив) | `cpu.mem` — Proxy над `_lab_read_ram` | `cpu.mem` — Proxy над `_lab_read_ram` |
| размер RAM | 2048 | 65536, **зашит в Proxy** | `_lab_ram_size()`, **динамический** |
| кадр | `frame()` | `frame()` | `frame()` |
| ввод | `buttonDown/Up(port,index)` | `buttonDown/Up(port,index)` | `_lab_tick(mask, mask2)` |
| снимок состояния | `toJSON` / `fromJSON` | `toJSON` / `fromJSON` | `toJSON` / `fromJSON` |
| **запись в RAM** | `cpu.mem[a]=v` **работает** | **НЕТ**: у Proxy только `get` | **НЕТ**: у Proxy только `get` |

Объявленные платформы (`platforms.js`, уже в репозитории):

| платформа | ядро | кнопок | RAM, байт |
|---|---|---:|---:|
| NES | JSNES | 8 | 2 048 |
| Mega Drive | Genesis Plus GX | 8 или 11 (A B C Start + 4 направления + X Y Z Mode) | 65 536 |
| GB / GBC | Gambatte | 8 | 32 768 |
| SNES | Snes9x | 12 | 131 072 |

## 2. Четыре конкретных блокирующих несоответствия

Это не «надо будет обобщить», а измеримые места, где текущий AGOD откажет или соврёт.

| # | Где | Что именно | Следствие |
|---|---|---|---|
| B1 | `agod-causal.js`, `CAPS.maxRamBytes = 65536` | у SNES RAM **131 072** байта | половина RAM SNES недоступна причинному движку; это не деградация, а молчаливое усечение |
| B2 | `agod-pipeline.js`, `DEFAULTS.masks = [1,2,4,8,16,32,64,128]` | ровно **восемь** одиночных масок | на Mega Drive (11) и SNES (12) часть кнопок **не нажимается ни разу**. Это тот же дефект, что в S8 съел Select на NES, только больше |
| B3 | `retro-core.js` | ввод через `_lab_tick(mask, mask2)`, а не `buttonDown/buttonUp`; у Sega нетривиальная раскладка бит в `input[]` | драйверный контракт `run(mask, frames)` требует **таблицы соответствия на платформу**, иначе «маска 64» означает разные кнопки на разных системах |
| B4 | `sega-core.js`, `retro-core.js` | `cpu.mem` — Proxy **только для чтения** | контрфактические пробы S4c (`driver.poke`) и критерий 5 ранжирования S9 **невозможны** нигде, кроме NES. Это не «пока не проверено»: инструмента нет |

## 3. Предлагаемый адаптер

Один интерфейс, реализуемый по одному разу на платформу. AGOD не должен знать, какая
это система.

```
PlatformAdapter {
  // наблюдение
  ramBytes()                 → размер RAM, запрашивается, а не предполагается
  readRam()                  → типизированный массив длины ramBytes()
  writeRam(address, value)   → либо запись, либо объявленный отказ UNSUPPORTED
  frameBuffer()              → {width, height, pixels} или null

  // действие
  buttons()                  → [{index, label}], длина платформенная
  singleButtonMasks()        → все одиночные маски, выводятся из buttons()
  press(mask, frames)        → нажатие маски на N кадров
  neutral(frames)            → то же для пустой маски

  // состояние
  snapshot() / restore(s)    → уже есть у всех четырёх ядер
  reset()                    → либо сброс, либо объявленный отказ UNSUPPORTED

  // объявленная честность
  capabilities()             → что именно платформа НЕ умеет, явным перечислением
}
```

Два правила, без которых адаптер бессмысленен:

1. **`capabilities()` объявляет отсутствие, а не умалчивает о нём.** Если `writeRam`
   недоступен, критерий 5 ранжирования и пробы S4c должны получить
   `NOT-SUPPORTED-ON-THIS-PLATFORM`, а не `NOT-TESTED` и уж точно не «потребитель не
   обнаружен». Разница между «не умеем проверить» и «проверили, эффекта нет» — это
   ровно та разница, из-за которой S4c пришлось переписывать.
2. **Маски выводятся из `buttons()`, а не из константы.** Любой список масок,
   записанный в AGOD, — это дефект B2, ожидающий своей платформы.

## 4. Порядок работ, если он будет разрешён

Отдельными стадиями, каждая со своим отчётом, ни одна не начинается сейчас.

| стадия | содержание | почему в этом порядке |
|---|---|---|
| X1 | адаптер + `capabilities()`, NES как единственная реализация; AGOD переводится на адаптер **без изменения поведения**, с побайтовой регрессией против опубликованных отчётов | перенос интерфейса и перенос платформы — две разные работы, и смешивать их нельзя |
| X2 | снять B1 и B2: размер RAM и список масок запрашиваются у адаптера; на NES результат обязан не измениться | это исправление **текущих** дефектов, которое полезно и без других платформ |
| X3 | `writeRam` в ядрах Sega и retro (экспорт `_lab_write_ram`) либо объявленный отказ | без этого критерий 5 и S4c мертвы вне NES |
| X4 | по одной платформе за раз: адаптер, шлюз пригодности S8, фазовый прибор, затем bounded AGOD | фазовый прибор S8 завязан на 8 кнопок и на разностное видео — его переносимость сама требует проверки |

## 5. Чего этот план не обещает

- Перенос **не** приблизит подтверждённую цель. На NES её нет (S8: 10 процедур из 10
  отказ; S9 — см. отчёт 21), и у других платформ нет причин вести себя иначе.
- `GAMEPLAY_REACHED` на другой платформе потребует **своей** процедуры входа и своего
  положительного контроля: развёртка S8 показала, что вердикт фазы условен относительно
  процедуры, и переносить пороги между платформами нельзя.
- Соответствие оригинальному железу ни на одной платформе не проверяется и не
  заявляется. Все статусы остаются core-local.
