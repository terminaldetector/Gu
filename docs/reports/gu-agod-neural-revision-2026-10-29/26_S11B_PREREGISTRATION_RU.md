# S11B: предрегистрация до запуска на реальных ROM

Публикуется **до** первого прогона S11B на реальных картриджах. Ни один параметр ниже
не меняется после просмотра предварительных результатов — ни сокращается, ни
расширяется ради улучшения статистики.

Коммит предрегистрации указан в `logs/s11b_preregistration.json`.

## 1. Вопрос стадии

S10B установил: при 12-кадровой причинной проверке **ни один из шести** реальных
кандидатов не получает причинного подтверждения. Но сравнение с типизацией некорректно
по **двум независимым** параметрам:

| параметр | типизация | причинная проверка S10B |
|---|---|---|
| временной горизонт | до **720** кадров | **12** кадров |
| структура воздействия | **60** циклов HOLD=4 / RELEASE=8 | **одно** удержание маски |

S11B должен раздельно установить, что значит длительность наблюдения и что — структура
воздействия. **Не** менять одновременно типизатор, стартовое состояние, причинный
предикат и правила NEGATIVE.

## 2. S11B-A — Continuous-Hold Horizon Sweep

Длительное удержание одной кнопки. Горизонты, объявленные заранее:

```
[12, 48, 120, 240, 480] кадров
```

Для каждого кандидата и каждого горизонта:

| плечо | назначение |
|---|---|
| действующее | маска кандидата удерживается весь горизонт |
| нейтральное | **та же** продолжительность, маска 0 |
| повторный нейтральный контроль | детерминизм: два нейтральных плеча обязаны совпасть |
| альтернативная маска | специфичность к кнопке |
| нейтральная траектория | фазовый сдвиг, допуск **фиксирован заранее**: `shiftTolerance = 3` |

`agod-causal.js`: по умолчанию `maxFramesPerArm = 120`, жёсткий CAP = **600**. Для
горизонтов 240 и 480 передаются **явные `limits`** в изолированном эксперименте.
Production и стандартные ограничения AGOD **не меняются**.

Проверяется не только итоговое значение RAM, но и **произошло ли изменение внутри
наблюдаемого интервала**. Изменение, присутствующее и под нейтральным управлением,
подтверждением причинной связи **не считается**.

## 3. S11B-B — Pulse-Train Causality

Воспроизведение структуры событий типизации. Фиксировано: `HOLD = 4`, `RELEASE = 8`.

```
импульсов: [1, 4, 12, 30, 60]
горизонты: [12, 48, 144, 360, 720] кадров
```

У каждой действующей последовательности — нейтральный контроль с **идентичными**
продолжительностью, интервалами и точками выборки.

Порядок одного опыта:

1. Восстановить **одно и то же** исходное состояние для действующего и нейтрального плеч.
2. Выполнить заранее объявленную последовательность.
3. Снимать RAM **после каждого полного цикла**.
4. Записывать интервалы появления изменений.
5. Повторить с альтернативной маской.
6. Проверить воспроизводимость на независимых стартовых состояниях.
7. Отделить зависимые от времени события от событий, вызываемых кнопкой.

**`Causal.probeAction` для этого не годится напрямую**: он удерживает одну маску весь
кадровый интервал. Передавать 720 в `frames` **запрещено** — это и подменило бы
структуру воздействия, и превысило бы жёсткий лимит плеча (600). Pulse-train
реализуется **отдельным экспериментальным адаптером** с теми же принципами
нейтрального, альтернативного и независимого контроля. Правила стандартного причинного
детектора при этом не меняются.

## 4. Диагностические исходы — каждый со своей интерпретацией

Объединять их под общей меткой `CAUSAL_RECOVERED` **запрещено**:

| исход | что означает |
|---|---|
| `RECOVERED_BY_DURATION` | изменение появляется при длительном удержании и отсутствует при коротком |
| `RECOVERED_BY_CADENCE` | изменение появляется после нескольких фронтов нажатия и отсутствует при непрерывном удержании **той же** длительности |
| `TIME_EXPLAINED` | изменение появляется и под нейтральным управлением спустя то же время |
| `NOT_REPRODUCIBLE_ACROSS_STARTS` | воспроизводится на одном старте и не воспроизводится на другом |
| `TRANSIENT_WITHIN_WINDOW` | обнаружено в промежуточном снимке и исчезает к концу длинного окна |
| `NOT_OBSERVED` | события нет |
| `NOT_COMPARABLE` | состояния несопоставимы (фазовый прибор: `NOT-REACHED` / `UNCONFIRMED`) |
| `BUDGET_EXCEEDED` | исчерпан объявленный бюджет |

**Ни один из этих исходов не является доказательством бесполезности игрового ресурса.**

## 5. Контрольный корпус

Основная сравниваемая группа — **прежние кандидаты S11A и S10B**. Дополнительные
кандидаты S11C учитываются **отдельно**.

Обязательные синтетические проверки:

| механизм | что проверяет |
|---|---|
| `lives` — многократно уменьшающийся ресурс | положительный контроль |
| `singleUnit` — одноразовый настоящий ресурс | один переход, ресурс |
| `oneShotSwitch` — одноразовый переключатель | один переход, не ресурс |
| те же два после **четвёртого** фронта | переход внутри окна |
| `firstThenLater` — изменение на первом событии и второе позднее | пересечение порога S11A только с предварительной выборкой |
| `frameCounter` — временной счётчик | изменение независимо от управления |
| `sacrifice` — потеря в обмен на сохраняющуюся выгоду | различитель цены и жертвы |
| `rate-trap` — рост поля без доказанной полезности | ловушка |

Реальные игры — без изменений: `lifeforce` 1/60, `lifeforce` 6/60, `contra` 6/300, те же
ROM, процедуры входа и платформенное ядро.

## 6. Контроль стартовых состояний

Для каждого горизонта и каждой маски — **одни и те же заранее объявленные** стартовые
состояния. Стартовая процедура **не меняется** после обнаружения подходящего результата.

Раздельно записывается:

| уровень | смысл |
|---|---|
| `SINGLE_SAVESTATE_REPLAY` | воспроизводимость одного savestate |
| `MULTIPLE_SAVED_STATES` | подтверждение на различных сохранённых состояниях |
| `INDEPENDENT_HISTORIES` | подтверждение на независимых игровых историях |
| `PHASE_ATTESTED` | аттестация игровой фазы фазовым прибором |

Траектория с аттестацией `NOT-REACHED` или `UNCONFIRMED` **не попадает** в статистику
подтверждённой сопоставимости и остаётся диагностической.

**Одинаковый state hash — не независимая история.** HOLDOUT сохраняет фактическую
независимость от процедуры выбора.

## 7. Бюджет и правила остановки

| параметр | значение |
|---|---|
| максимум кандидатов | **6** (прежняя группа S10B) + до **4** дополнительных S11C, учитываемых отдельно |
| независимых стартов на опыт | **3** |
| общий лимит эмулированных кадров | **4 000 000** |
| допуск фазового сдвига | `shiftTolerance = 3`, фиксирован |
| правило остановки | исчерпание общего лимита кадров → `BUDGET_EXCEEDED`; исчерпание на кандидате → его результат `BUDGET_EXCEEDED`, следующие кандидаты не оцениваются |
| ревизия причинного детектора | `agod-causal-e3-2` |
| ревизия типизатора | `agod-ram-e2-1` |
| контрольные коммиты | S11A `9baf883`, S11C `6c116a1` |

## 8. Учёт вычислительной стоимости (ревью 1.2)

Раздельно, по каждому опыту:

- эмулированные кадры;
- число снимков RAM и прочитанных байт;
- CPU / wall-clock;
- число оценок кандидатов.

## 9. Главный результат стадии — три величины

| | вопрос |
|---|---|
| **A** | сколько кандидатов не обнаруживалось **из-за короткого горизонта** |
| **B** | сколько кандидатов не обнаруживалось **из-за неправильной структуры воздействия** |
| **C** | сколько изменений остаются невоспроизводимыми либо объясняются временем, фазой игры или другими механизмами |

Рост числа наблюдаемых RAM-изменений **успехом не является**. Результат должен показать
именно независимое отличие действия от нейтрального хода игры. `VERIFIED_GOAL` целью
стадии не является.

## 10. Неизменно

NEGATIVE verification, HOLDOUT и правила независимости, ранжирование S9, исходные ROM,
принятые процедуры входа, FIRST-V1 как контроль, production, отдельность
cross-platform. Правило двух переходов S11A — **выключено** и не перенастраивается.
`PRE_AND_POST` по умолчанию **не включён**.
