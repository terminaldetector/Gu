# AGOD-08/09 — Реестр доказательств и первая самостоятельно подтверждённая цель

Статус: **построено и измерено. PASS на контролируемом семействе.** Закрыт разрыв,
зафиксированный в E4: `VERIFIED` больше не приходит фикстурой — цель, выведенная из
самого картриджа, доходит до `VERIFIED` через непересекающиеся holdout-доказательства,
и только после этого брокер выдаёт число.

- Модуль: `app/src/main/assets/lab/agod-evidence.js` (новый, **ничем в продакшене не импортируется**)
- Проверка: `tools/agod_evidence_check.cjs`
- Данные: `logs/evidence_report.json`, лог `logs/agod_evidence_check.log`
- Существующих файлов GU не изменено ни одного

## 1. Что именно требовалось решить

ТЗ формулирует два отдельных требования, и оба легко имитировать:

1. **Независимость доказательств (AGOD-08).** «Новый UUID» не является новым
   доказательством. Если гипотеза подтверждена дважды из одного и того же
   сохранения, это одно наблюдение с двумя именами.
2. **Кто имеет право выдать `VERIFIED` (AGOD-09).** «Кэш не вправе самостоятельно
   повышать гипотезу до `VERIFIED`».

Реестр отвечает на оба, выводя идентичность старта из того, **чем он произведён**:

```js
function startKeyOf(item){
 return digest([romHash,coreRevision,
  text(item.parentStateHash,'parentStateHash'),
  (item.restorePath||[]).join('>')]);
}
```

Идентификатор записи в ключ **не входит**. Переименовать старт нельзя.

## 2. Два разных понятия, которые легко спутать

| Понятие | Чем является | Как считается |
|---|---|---|
| **Раздел (partition)** | свойство данных, не гипотезы | старт, однажды попавший в `DISCOVERY`, не может быть holdout **ни для какой** цели |
| **Повторное использование (reuse)** | свойство пары «цель + старт» | один старт, поддерживающий две разные гипотезы внутри своего раздела, законен и остаётся независимым |

Это различие было внесено после первой реализации, где раздел и повторное
использование считались одной сущностью: там вторая гипотеза, опирающаяся на те же
старты, ошибочно исключалась как утечка.

## 3. Сквозная цепочка на реальном картридже (часть A)

Для каждого из 7 картриджей три раздела прогоняются **независимо**: свои стартовые
состояния, своё исчерпание ресурса, свой вердикт. Общий у них только ROM.

```
pristine → DISCOVERY  (neutral+11)  → причинный зонд → исчерпание → induceGoal → 2 записи
pristine → CALIBRATION(neutral+53)  → причинный зонд → исчерпание → induceGoal → 2 записи
pristine → HOLDOUT    (neutral+97)  → причинный зонд → исчерпание → induceGoal → 2 записи
                                   ↓
                     assess → CALIBRATED, disjoint, liveHoldout
                                   ↓
                     promote → VERIFIED (6 ссылок на доказательства)
                                   ↓
                     broker.claim → VERIFIED, value = −1
```

| Метрика | Результат |
|---|---|
| Цель, доведённая до `VERIFIED` собственными доказательствами | **7 / 7** |
| Выплата брокера по самостоятельно подтверждённой цели | **7 / 7** (`value = −1`) |
| Старты разделов пересеклись | **0 / 7** (проверено по ключам стартов) |
| Накопитель доведён до `VERIFIED` | **0 / 7** |
| holdout, пересобранный из стартов discovery, дал `VERIFIED` | **0 / 7** |

Трек жизней во всех разделах и на всех семенах: `3 → 2 → 1 → 0 → 0 → 0 → 0`.

### 3.1. Отрицательные контроли внутри части A

Проходящий тест ничего не стоит, если он не способен провалиться. В часть A
встроены два контроля **на тех же реальных данных**:

- **Накопитель.** Для счёта регистрируются такие же доказательства во всех трёх
  разделах. Повышение отклоняется: `polarity is not independently evidenced`,
  `polarity is not usable for reward`. Реестр **не является обходным путём к
  `POSITIVE`** — блок из E4 сохраняется и при полном комплекте доказательств.
- **Подменённый holdout.** Те же наблюдения регистрируются во второй реестр, где
  holdout собран из стартов discovery. Повышение отклоняется: записи holdout
  исключены как утечка раздела, остаётся `no holdout evidence`.

## 4. Атака на реестр (часть B): 13 отказов

| Сценарий | Что получено |
|---|---|
| holdout использует старт discovery | запись `EXCLUDED` («leak evidence across partitions»), повышение отклонено |
| тот же parent state под новым идентификатором | `independent:false`, `reuseOf` указывает на первую запись; счёт независимых стартов остаётся 1 |
| повышение только из восстановленного кэша | `CALIBRATED`, но `liveHoldout:false` → «a cache cannot promote a hypothesis» |
| противоречащее доказательство после `VERIFIED` | `CONTRADICTED`, список подтверждённых целей пуст |
| явный `contradict()` | `revokedPriorVerification:true` |
| контрольный эпизод в роли holdout | `EXCLUDED`, повышение отклонено |
| доказательства старше TTL реестра | `EXPIRED`, повышение отклонено |
| полярность не подтверждена независимо | отклонено |
| полярность `UNKNOWN` при полном комплекте | отклонено |
| чужая ревизия профиля | отклонено |
| holdout без калибровки | отклонено |
| импорт состояния от другого ROM | исключение при импорте |
| доказательств нет вовсе | `UNKNOWN`, без числового ключа |

### 4.1. Исправление, сделанное по ходу

Первая версия `promote()` возвращала сразу три блокера («нет holdout», «holdout
пересекается», «holdout только восстановленный»), когда holdout не было вовсе.
Два из трёх в этом случае — ложные утверждения о несуществующих данных. То же
касалось противоречащей и просроченной гипотез: короткое замыкание `assess()`
обнуляет счётчики, и отчёт рапортовал отсутствие калибровки, которая на самом деле
была. Исправлено: блокеры holdout стали взаимоисключающими, а `CONTRADICTED`/
`EXPIRED` возвращают ровно одну причину. Числовые результаты это не меняет, но
сообщения реестра — часть его показаний, и они не должны врать.

## 5. Чего AGOD-08 НЕ сделал

1. **Старты «независимы» в слабом смысле.** Три раздела получены из одного и того
   же состояния после загрузки, разным количеством нейтральных кадров (11 / 53 / 97).
   Их родительские состояния различны, и реестр по своему определению считает их
   разными стартами — но это не независимые игровые сессии. На реальной игре
   потребуются разные уровни, позиции и входные предыстории.
2. **Исчерпание ресурса по-прежнему ведёт чекер** (маской из оракула), а трек жизней
   читается по адресу из оракула. Сами модули оракула не видят, но автономного
   поиска ресурса здесь нет.
3. **TTL — параметр, а не измерение.** 48 часов взяты по умолчанию; корректный
   горизонт устаревания доказательства не исследовался.
4. **Дайджест ключа старта — не криптографический.** Этого достаточно, чтобы
   различать старты, и этого недостаточно для защиты от подделки.
5. **Персистентность не проверена в реальном хранилище**: `exportState`/`importState`
   прогнаны в памяти, формат Layer Set не затронут.
6. Измерено на одном синтетическом семействе. Blind-корпус §11.1 не существует.
7. Android не затронут; стоимость реестра на устройстве не измерялась.
