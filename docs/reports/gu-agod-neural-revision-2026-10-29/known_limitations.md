# Известные ограничения (на момент закрытия E0)

Список ведётся накопительно. Каждый пункт — либо ограничение базы GU, либо ограничение
окружения этой итерации. Пункты не снимаются без нового измерения.

## A. Ограничения окружения этой итерации

| # | Ограничение | Следствие | Как снять |
|---|---|---|---|
| A1 | emscripten отсутствует | `fdb_game_check.cjs`, `expanded_game_check.cjs`, `retro_check.cjs` не запускаются; SNES/GB-ядра не собрать | CI-образ с emscripten 3.1.57 или предсобранные ядра |
| A2 | Нет физического Android-устройства | Все пункты G6 — `DEVICE-PENDING`; FPS, battery, thermal, ANR не измерены | прогон на реальных устройствах |
| A3 | Разделяемый 4-vCPU контейнер, одиночные прогоны | Любые тайминги имеют неизмеренный разброс; сравнивать по ним нельзя | повторные прогоны со статистикой |
| A4 | Python 3.13 вместо 3.11 в CI | Отличие среды; отказов не вызвало, но не идентично CI | зафиксировать версию |
| A5 | Maven Central может вернуть HTTP 429 | `check.sh` падает на загрузке `json.jar`; транзиентно | повтор; SHA256 jar запинен и проверен |
| A6 | Gradle/APK-сборка и UI-suite не выполнялись | Сборочный и UI-уровень базы не подтверждён этой итерацией | отдельный прогон |

## B. Ограничения базы GU, подтверждённые измерением

| # | Ограничение | Доказательство |
|---|---|---|
| B1 | Полный тип игровой переменной не определяется ни разу | `fullTypeIdentified` = 0/7 на контролируемых ROM |
| B2 | Точный типизированный кандидат счётчика находится в 1 случае из 7 | воспроизведено, совпадает с ТЗ §2.1 |
| B3 | Причинности нет: независимых подтверждений 0 | `independentConfirmations` = 0 на всех 7 ROM |
| B4 | Подтверждённой награды нет: `verifiedRewards` = 0, `rewardStatus` = `UNKNOWN` везде | прогон `agod_rom_check.cjs` |
| B5 | Полярность цели не определяется: `goalPolarity` = `unknown` на всех 7 ROM | там же |
| B6 | cycle timestamp остаётся `UNKNOWN` | заявлено в ТЗ §2.2, в прогоне не опровергнуто |
| B7 | bank provenance для неподтверждённых mapper — `UNKNOWN` | `unsupportedMapper: UNKNOWN` в выводе трассировки |
| B8 | Остаточное замедление после отключения трассировки не устранено | detached p50-отношение 1.285×–1.525× против baseline |

## C. Расхождения с ТЗ, найденные в E0

| # | Расхождение | Суть |
|---|---|---|
| C1 | Числа overhead из ТЗ §2.2 (1.386× active, 1.201× detached) не воспроизводятся устойчиво | Два прогона на одном коммите дали 1.526×/1.525× и 1.394×/1.285×. Значения ТЗ — снимки единичных прогонов, а не характеристика механизма |
| C2 | Формулировка ТЗ §2.1 «точный типизированный кандидат найден только в 1/7» верна только про счётчик | По жизням точный типизированный кандидат найден 7/7; про детектор в целом формулировка занижает результат |
| C3 | Порог G6 (≤10% overhead пассивного наблюдения) уже напряжён на базе | Измеренное отношение probe/core на хосте 7.0%–10.4%; худший ROM на границе порога ещё до причинной проверки и нейросети |

## C2. Ограничения причинного движка E3 (новое)

| # | Ограничение |
|---|---|
| C2.1 | Измерено только на синтетическом семействе генератора проекта; blind-корпус §11.1 не существует |
| C2.2 | Только односкнопочные маски, удерживаемые всё окно: комбинации, короткие нажатия и отпускания (NN-03) не проверялись |
| C2.3 | Зонд дорогой: 10 плеч на старт и маску (~3840 эмулированных кадров на картридж); стоимость на Android не измерялась |
| C2.4 | Допуск на временной сдвиг ±3 итерации подобран под наблюдаемый сдвиг 1–3; на играх с большей вариативностью нагрузки может потребоваться иное значение, и это не исследовано |
| C2.5 | Движок устанавливает только «действие меняет адрес». Полярность, роль, цель и награда остаются `unknown`/`UNKNOWN` по построению |
| C2.6 | Работает лишь по восстановленным снимкам в изоляции; к живой сессии не применялся и не предназначен |

## C3. Ограничения индукции целей и награды E4 (новое)

| # | Ограничение |
|---|---|
| C3.1 | ~~`VERIFIED` недостижим изнутри модулей E4~~ — **снято AGOD-08**: реестр построен, цель доходит до `VERIFIED` собственными доказательствами (7/7). Ограничения самого реестра — в разделе C4 |
| C3.2 | `POSITIVE` полярность принципиально не выводится изнутри эмулятора; это ограничение метода, и для неё необходим внешний оракул или калибровка человеком |
| C3.3 | Подавление игры измеряется по области адресов, заданной вызывающей стороной: отделить служебное эхо ввода от игрового состояния в общем виде не решено |
| C3.4 | Калибровка уверенности не делалась: `confidence` всегда `null` |
| C3.5 | Переходы жизненного цикла `CONTRADICTED/INVALIDATED/EXPIRED` в **индукции** по-прежнему не используются; в реестре они реализованы и проверены |
| C3.6 | Измерено на одном синтетическом семействе; фазы `BOOT/PAUSED/RESPAWN/TRANSITION/COMPLETE` не наблюдались и не проверялись |

## C4. Ограничения реестра доказательств AGOD-08 (новое)

| # | Ограничение |
|---|---|
| C4.1 | «Независимые» старты получены из одного состояния после загрузки разным числом нейтральных кадров (11/53/97). Родительские состояния различны, но это не независимые игровые сессии: на реальной игре нужны разные уровни, позиции и предыстории ввода |
| C4.2 | Исчерпание ресурса ведёт чекер маской из оракула, трек читается по адресу из оракула; автономного поиска ресурса нет (модули оракула не видят) |
| C4.3 | TTL доказательства (48 ч) — значение по умолчанию, а не измерение: корректный горизонт устаревания не исследовался |
| C4.4 | Дайджест ключа старта стабилен, но не криптографичен: от подделки не защищает |
| C4.5 | Персистентность проверена только в памяти; формат Layer Set и реальное хранилище не затрагивались |
| C4.6 | Реестр измерен на том же синтетическом семействе; на Android не запускался, его стоимость не измерялась |

## C5. Ограничения типизации RAM E2 (новое)

| # | Ограничение |
|---|---|
| C5.1 | Знаковость принципиально не определяется: беззнаковое и дополнительное до двух прочтения дают одинаковые модульные шаги. Всегда `UNKNOWN` |
| C5.2 | Полная ширина доказуема только при наблюдённом переносе в каждый байт. У BCD-счётчика ширины 4 со старта 9 это недостижимо (seed 7) — сообщается младшая активная компонента |
| C5.3 | Кодировка не определяется, когда все цифры ≤ 9 (BCD и двоичное прочтение дают одно число): у жизней 0/7, сообщается класс эквивалентности |
| C5.4 | Выборка «одно событие — один снимок» задаётся вызывающей стороной; автономного определения «что считать событием» нет |
| C5.5 | Роль, полярность и смысл переменной модулем не выводятся вообще |
| C5.6 | Нейтральный контроль исключает времязависимые байты, но не байты, которые действие изменяет *через* таймер |
| C5.7 | Режим дорогой: 150 событий на маску × 8 масок на картридж; стоимость на Android не измерялась |
| C5.8 | Визуальный HUD (AGOD-03) не делался: продакшен-UI менять нельзя, устройства нет, непроверяемый оверлей не нужен |

## C6. Ограничения нейроагента E5 (новое)

| # | Ограничение |
|---|---|
| C6.1 | Среда — три действия на контролируемом картридже; признаки скалярные (нормированный ресурс, флаг исчерпания, one-hot предыдущего действия). Пикселей, свёрток и кадровых стеков нет |
| C6.2 | Оптимальная политика проста («не нажимай штрафуемую кнопку»): результат доказывает корректность механизма, а не способность решать игры |
| C6.3 | Необученная политика не зависит от картриджа, поэтому эффективный размер выборки контроля — 6 сидов агента, а не 42 прогона |
| C6.4 | Сравнения с опубликованным baseline нет: ни SB3, ни другие проекты здесь ничего не запускали |
| C6.5 | Гиперпараметры не подбирались: 400 шагов обучения, 60 оценки, γ=0.95, скрытый слой 24, Adam — взяты одни значения и оставлены |
| C6.6 | Внутренняя мотивация (novelty) не используется, хотя канал в брокере есть |
| C6.7 | Android не затронут; стоимость обучения на устройстве не измерялась. С FDB, `Engine` и форматами Layer Set модуль не связан |
| C6.8 | Отделение эха ввода от игрового состояния («сохраняется после отпускания») работает для этого способа реализации эха; эхо с защёлкой так не отделится |

## D. Явно не проверявшееся (во избежание ложного впечатления)

- Blind-корпус ROM из §11.1 не существует и не собирался.
- Independent oracle из §11.2 не существует.
- В базе GU нейросетевого обучения нет. В E5 построен отдельный экспериментальный учащийся: NN-01 (Double DQN, replay, target-сеть, checkpoint) проверен, NN-02…NN-08 — нет.
- Визуальный HUD обнаружения (AGOD-03) не реализован и не проверялся.
- Никаких заявлений о поведенческом улучшении в игре не делается: измеренное поведение — избегание штрафуемого действия на синтетическом картридже.
