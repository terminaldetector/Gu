# FDB: первая реализация по ТЗ 15–16 октября 2026

Статус: исследовательская feature-ветка, не объявление нового стабильного релиза.
База: `1d6313ba67624d57be226c215c78143400af428b`, `v2/gmode-fdb-gpu`.
Ветка: `feature/fdb-credit-gpu-v5`. PR: https://github.com/terminaldetector/Gu/pull/6.

## Что реализовано

1. **Sparse GPU sync.** Отдельные монотонные ревизии ROOT, структуры Wexo, весов Wexo и порогов; прежний `GraphDelta.version()` сохранён. Rollback помечает все категории изменёнными. План собирается из согласованного снимка под блокировкой слоя и подтверждается только после успешных GL-вызовов.
2. **ROOT upload.** Реально изменённые CSR-индексы объединяются в непрерывные диапазоны; удаление ΔW восстанавливает W₀. Разреженные изменения не вызывают загрузки всего W₀. На fixture с 2048 соседними индексами: 2048 отдельных вызовов в старом коде против 1 диапазона в новом. На разрозненных индексах уменьшение числа вызовов может отсутствовать.
3. **Wexo upload.** Изменение веса использует прежнюю позицию в overlay и не перестраивает adjacency. Рождение/удаление вызывает перестройку overlay. Изменение только порога не затрагивает ROOT/Wexo. Проверка q24.8 использует лишь затронутые назначения вместо копирования полного массива входящих весов. Отложенные события не сбрасываются.
4. **Выключаемый credit.** Пять профилей пластичности остаются прежними. Независимый параметр `learning.creditProfile`: `single-v1` — старое правило по умолчанию; `dual-v1` — fast/slow; `dual-rate-v1` — fast/slow с пробным локальным rate proxy для порогов. Новые значения доступны в разделе обучения и в JSON отдельных акторов.
5. **Две временные шкалы.** Быстрый синаптический след: прежние τ=0.6 секунды исполненного игрового времени и ограничение ±2. Медленный: затухание `exp(-1/8)` на подтверждённый outcome, вклад текущего gradient, ограничение ±2 и сброс после 16 подтверждений без нового ненулевого вклада. Credit смешивается 50/50. Это ограниченный экспоненциальный агрегат, не точный буфер последних 16 действий. Время ожидания backend не добавляет вклад.
6. **Rate proxy.** Только одинаковые маски действий и длительности окон, последовательные подтверждённые измерения. Множитель `clip((Hz_current-Hz_previous)/250, -1, 1)` применяется к прежнему activity/action proxy. Первое и несопоставимое окно даёт нулевой новый rate-вклад; saturation guard и ±5 mV сохранены. Это разность оконных частот, не измеренная причинная производная порога. Медленная часть относится к синаптическим следам; пороговые следы сохраняют прежнюю быструю динамику.
7. **Guards.** Изменившаяся lesion-конфигурация отвергает cached decision целиком; проверка исполненной маски сохранена. Новый профиль не расходует trace-table на нулевые градиенты. Отказ старого outcome не удаляет уже созданное следующее решение. Boundary, человеческий пример, смена профиля и загрузка игрового слоя очищают временной credit. Frozen feedback и evaluation не изменяют learner/RNG. Sampling RNG по-прежнему расходуется при обучающем выборе действия, а не откатывается после позднего отказа outcome.
8. **Сохранения.** Старый профиль продолжает писать learning v4; экспериментальные пишут v5. Внешний FDB остаётся v3, Layer Set v2, threshold state v1. Декодирование списка связей теперь предварительно проверяет весь payload на staging-слое: ошибка во втором списке не оставляет частично применённый первый.
9. **Диагностика.** Локальный JSON: top-20 ROOT с W₀/ΔW/effective weight, Wexo с utility/evidence при наличии, пороги, последние 100 принятых/отвергнутых outcomes с reward/advantage, реальными числами мутаций, birth/prune и бюджетом. ID нейронов — строки. Снимок до/после показывает также удаления и отрицательные веса. Экспорт проверяет ROM/граф/порядок портов и защищён от смены контекста во время ожидания.
10. **Измерения задержек.** Worker queue, native configure, total sample, GPU sync и счётчики загрузок; feedback, сборка JSON-состояния, запись на диск, round-trip и применение ответа WebView; этапы переключения профиля от клика до ACK/сохранения. Последние 100 измерений каждого вида дают p50/p95/p99. Сборка объекта JSON не равна стоимости его окончательного кодирования/доставки: последняя входит в round-trip, отдельно не измерена. Первый GL sync после configure измеряется следующим sample. Это локальная сессионная статистика, не подтверждённое ускорение телефона.
11. **Размер.** Native configure принимает до 4 MiB UTF-8, согласованно с лимитом Layer Set; прежде его ограничение 1 MiB могло отвергнуть допустимое сохранение. Лимит самого Layer Set не увеличен.

## Совместимость

| Источник | Чтение / продолжение |
|---|---|
| learning v1 | Существующие счётчики; история не выдумывается |
| v2 | Существующая миграция, temporal eligibility сбрасывается |
| v3 | Прежнее чтение с проверкой портов/кандидатов |
| v4 → single-v1 | Прежний лабораторный exact roundtrip |
| v4 → эксперимент | Веса/utility/evidence/RNG сохраняются, быстрый/медленный temporal credit очищается |
| v5 → тот же профиль | Exact лабораторный roundtrip, включая rate context; pending decisions не сериализуются |
| v5 → другой профиль / single-v1 | Устойчивое знание сохраняется, временные следы очищаются |
| Layer Set → игра | Native boundary очищает временные следы и rate context; живое состояние ROM/LIF не восстанавливается этим файлом |
| Новый v5 → старая сборка приложения | Старый читатель отвергнет v5. Для возврата сначала переключить слой в single-v1 и сохранить v4; исходные наборы рекомендуется хранить отдельно |

W₀, graph SHA, порядок портов, платформенная/ROM identity и раздельные P1/P2 сохранены. Новые профили не разрешают перенос между FlyWire и Male CNS. Shared Experience не изменялся: проверенный overlay переносится по прежним контрактам; v5 temporal state туда не копируется.

## Контрольный эксперимент

Файлы: `reports/fdb-2026-10-16/temporal.json` и `.csv`. Исходник: `tools/FdbTemporalExperiment.java`.

120 парных прогонов: шесть задач × пять заранее заданных seed (11, 23, 37, 53, 71) × четыре варианта. 80 обучающих эпизодов, 40 held-out; одинаковый бюджет действий для вариантов одной задачи. W₀ — 30-нейронный fixture с пятью исходными связями; действия выбирают существующие CPU LIF и `Decision`. Reward определяется правилами контролируемой задачи, без игровой эвристики в policy. Held-out меняет начальные состояния и частоту входа 500→450 Hz; это **не перенос на другую ROM**. Frozen control использует тот же движок. Оценка заморожена; дополнительно проверяется точное совпадение held-out после reload.

Ниже — средняя held-out доля успешных эпизодов по пяти seed, без заявления статистической значимости:

| Задача | Single | Dual | Dual + rate | Frozen |
|---|---:|---:|---:|---:|
| Немедленный результат | 56.5% | 61.5% | 61.5% | 50% |
| Последовательность из 3 действий | 4.5% | 8.5% | 9% | 0% |
| Удержание в 3 окнах | 46.5% | 45.5% | 46% | 50% |
| Награда через 5 решений | 50% | 55% | 55% | 50% |
| Награда через 10 решений | 50% | 52% | 52% | 50% |
| Reversal | 50% | 50.5% | 50% | 50% |

На удержании все обучаемые варианты хуже frozen; Dual хуже Single. Длинный delay и reversal остаются почти на случайном уровне. Rate proxy не показал устойчивого преимущества. На этих данных нельзя утверждать хорошую обучаемость произвольным играм; новые варианты **не включаются по умолчанию**. Sample efficiency, learning curves, AUC, `not reached`, разброс отдельных seed, CPU стоимость, оценка памяти и размер checkpoint доступны в JSON/CSV. Память — инженерная оценка, не RSS.

## Проверки и ограничения среды

- Базовый и новый `tools/check.sh`: Java/JS проверки до игровой WASM-части проходят. Локально оба останавливаются на одинаковом `Sega API6 required`: в checkout лежит старая Sega WASM, SNES/GB отсутствуют; это не полный зелёный suite. До изменений также отсутствовал `pyarrow`; зависимость установлена, прогон повторён на отдельном неизменённом checkout.
- Пройдены legacy learning/checkpoint, root/expanded, identity, projection cache, три синтетических графа с 8/12 портами, dual actor isolation/reload, 27 production JS feedback checks, reward и Shared Experience tests.
- Новые `FdbDualCreditCheck`, `GpuLayerSyncCheck`, `FdbDiagnosticsCheck`, `fdb_diagnostics_check.cjs`: PASS. Проверяются dual-delay, horizon, lesion/mask/freeze guards, v4/v5, malformed-state atomicity, rate context, диапазоны GPU/restore/retry и строковые 64-bit ID.
- `GPU_RUNTIME_GL_LIBRARY=libGL.so.1 python tools/gpu_runtime_check.py`: PASS на Mesa ES 3.2; production shader, signed weights, thresholds, pruning и отложенные события. Это тест шейдера; Java upload planner проверяется отдельным host-тестом. Ни один из них не равен драйверному тесту Android.
- Компиляция Java против официального Android API35 `android.jar`: PASS. Неизменённый OCR представлен compile-only заглушкой, поскольку локально нет MLKit; это **не Gradle build и не APK**.
- Установка локального Playwright Chromium не удалась: сервер загрузки вернул некорректный архив. UI browser suite должен пройти в Actions с его установленным браузером.
- **НЕ ПРОВЕРЕНО НА УСТРОЙСТВЕ:** p95/p99 телефона, battery/thermal, RSS и реальные GPU stalls. Длинные операции ожидания/сохранения пока измеряются, но не отменяются: сбрасывать подтверждённый опыт ради плавного переключателя нельзя.

CI: https://github.com/terminaldetector/Gu/actions?query=branch%3Afeature%2Ffdb-credit-gpu-v5 . Статус и ссылки на APK смотреть в фактически завершившемся запуске; этот документ не объявляет сборку успешной заранее. ## Для пользователя

В «Обучение» оставьте «Исходный · один быстрый след» для прежнего поведения. Для сравнения создайте отдельный Layer Set, выберите `Fast + Slow`, одинаковые seed и параметры награды. Смена правила сохраняет веса и ставит игру на паузу. В исследовательской вкладке «Снимок изменений FDB» фиксирует начало сравнения, «Отчёт FDB · JSON» выгружает локальный отчёт после опыта. Опыт может ухудшить поведение — это отражается в результате, а не скрывается подбором удачного seed.
