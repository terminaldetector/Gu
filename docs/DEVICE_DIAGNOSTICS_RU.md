# Журнал GU на Android

Начиная с 2.1.1 (versionCode 35) приложение автоматически ведёт локальный
диагностический журнал. Подключение компьютера, logcat, загрузка коннектома и
ручная оценка действий для этого не нужны. Запись начинается в Application,
до создания игрового экрана и нейронного worker.

## Как получить отчёт

1. Открыть **Настройки → Диагностика** либо **Быстрое меню → Диагностика**.
2. При необходимости добавить короткое наблюдение, например «звук отстаёт после
   возврата». Эта запись не меняет награду, веса или историю обучения.
3. Нажать **Сохранить диагностический отчёт** и выбрать место для ZIP в Android.

При завершении процесса WebView появляется нативный экран с той же кнопкой.
При ошибке запуска основного JavaScript доступен нативный диалог экспорта.
После аварии приложения журнал можно экспортировать при следующем запуске.
Очистка данных/удаление приложения удаляет внутренний журнал; уже экспортированный
ZIP остаётся в выбранном месте. Экспорт локальный, автоматической отправки нет.

## Какие сведения сохраняются

| Область | Данные |
| --- | --- |
| Идентичность | Версия приложения, отпечаток исходников, SHA256 установленного APK при экспорте, Android/WebView, устройство, ROM/core/graph и режим |
| Эмуляция | Открытие/перезапуск, пауза, реальные выполненные кадры, FPS, CPU-время кадра и интервалы завершения p50/p95/p99 |
| Нейросеть | Ошибки с token/generation, фактический backend, configure/sample/feedback timings, очередь worker, парные CPU-окна |
| Сохранения | Начало/конец, длительность, успех/ошибка, ROM/core, SHA256 поколения и восстановление резервной версии |
| Жизненный цикл | Activity/process, уход в фон, запрос сохранения, ACK/timeout/stale ACK, возврат, пересоздание |
| Отказы | JavaScript/console, uncaught Java, WebView renderer, пропуски heartbeat; на API 30+ доступная Android-история завершений процесса |
| Управление | Счётчики touch/key, ограниченная история последних изменений маски, подключение контроллера, Back, ориентация |
| Производительность | CPU/PSS/Java/native heap процесса приложения; доступные сырые показания батареи каждые пять секунд в foreground |
| Обучение | Краткие native-ответы history/curriculum/roles/evaluation, последние доступные метаданные эпизодов, frozen proofs и результаты сравнений |

Обычные события проходят через отдельную ограниченную очередь, критические события
синхронизируются с диском. В памяти JS до 200 последних событий, в очереди до 96;
native очередь до 128, журнал до восьми сегментов по 512 КиБ. Это скользящая история,
а не бессрочный архив всей игры. ZIP ограничивает дополнительные файлы и общий
объём; пропуски, ошибки записи и неполный хвост явно отражаются в отчёте.

Экспорт включает выбранные метаданные/доказательства, а не ROM, игровые снимки,
контрольные точки с весами, графы или скриншоты. Резервации сравнений, содержащие
candidate/reference checkpoints, в ZIP не включаются. Перед отправкой можно
просмотреть ZIP: он содержит JSON и JSONL, включая введённые заметки и сообщения
об ошибках. Секретные данные в заметки вводить не следует.

## Разбор без запуска приложения

```sh
python tools/inspect_diagnostics.py gu-diagnostics-123.zip --out inspection.json
```

Разборщик читает ZIP без извлечения, проверяет список/размеры файлов и SHA256,
затем переносимые SHA256 отдельных событий. Связывает begin/end операций,
отделяет успешные save/load от ошибок, показывает незавершённые операции,
пропуски последовательности, заметки, окна производительности и имеющиеся
frozen proofs. Повреждение даёт exit 2; целый архив — exit 0. Последнее означает
целостность отчёта, а не прохождение ТЗ. Java-экспорт и Python-разбор дополнительно
сверены на общей фикстуре с Unicode и малыми числами.

## Как будем сверять с ТЗ

У пользователя есть Android. Сначала завершаются кодовые остатки; проверка на
телефоне и разбор ZIP выполняются следующим шагом. Сейчас device-приёмка не
объявляется пройденной. При дальнейшей проверке нужны игровые сценарии NES,
Sega, GB/GBC и SNES с нейросетью и без неё, save/load, сменой ROM, фоном и возвратом.

Для каждого результата сверяются версия APK, точный ROM/core/graph, режим,
временной отрезок, фактические завершения операций, ошибки и потери журнала.
История рядом с исключением или перезапуском не превращает неподтверждённую
операцию в успешную. Наличие роли Best в ответе не доказывает улучшение поведения:
для этого нужны целые парные proofs, протокол и независимые игровые данные.

## Пределы измерений

- CPU и PSS относятся к процессу приложения. Отдельный процесс WebView renderer
  и весь телефон в эти цифры не входят. Значение CPU 100% — одно занятое ядро.
- FPS считает завершённые кадры ядра; это не измерение физических показов экрана.
  Интервалы и стоимость ядра сохраняются отдельно. Окна и квантили ограничены;
  не все параметры меняются ровно на границе замера, контекст дополнительно
  опрашивается раз в секунду.
- Счётчики starved/overrun отражают аудиотранспорт, а не доказанную синхронизацию
  звука и видео. GPU uploads/sync не означают загрузку GPU или расход энергии.
- Датчики батареи могут отсутствовать; неизвестное остаётся null. Сырые ток/заряд
  не заменяют контролируемый эксперимент по энергопотреблению.
- Heartbeat gap означает замеченную задержку, а не официальный Android ANR.
  На API 26–29 история ApplicationExitInfo недоступна. Неподтверждённый прошлый
  foreground сам по себе не объявляется аварией.
- При SIGKILL/отключении питания возможна потеря последних обычных событий.
  Fsync не даёт гарантии поведения накопителя при физическом отключении питания.
- Отсутствие ошибок в сохранённом фрагменте не доказывает отсутствие утечки
  памяти, правильность физического управления или функциональное обучение.
