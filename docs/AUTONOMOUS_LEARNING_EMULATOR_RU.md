# GU — Autonomous Learning Emulator

Техническое направление от 19 октября 2026 года. Приоритет продукта — обычная
стабильная игра, затем достоверное автономное обучение коннектома. Лаборатория
остаётся расширенным инструментом. Новые платформы и тяжёлые вычислительные режимы
не добавляются до закрытия P0. Этот документ задаёт последовательность работ;
описанный целевой цикл ещё не означает его полной реализации.

База реализации: `research/fdb-growth-audit` на `6d772bd167d5c7d61c2d069d37fa22687e6bf634`,
production-код из `v2/gmode-fdb-gpu` (`3462e05`). Работа ведётся в отдельной ветке
`feature/autonomous-learning-emulator`; закрытая исследовательская ветка не меняется.
`main` (`02d0de2`) содержит старую версию 1.0.1 и не соответствует описанному FDB API.

## Контракт продукта

```
Эмулятор → наблюдение → коннектом → действие → подтверждённая обратная связь
 → пластичность FDB → граница эпизода → опыт → независимая frozen-проверка
 → сохранить Current / подтвердить Best → следующий эпизод
```

Ручная игра доступна без графа и при отказе нейронного backend. Ошибка обучения
фиксируется явно; успешная эмуляция не превращает её в успешное обучение.
Ручные нажатия не являются положительной наградой. Отсутствие обнаруженного
прогресса — неизвестный результат, а не поражение и не числовая награда ноль.
Ноль допустим только как измеренная обратная связь известного источника.

| Данные | Содержание | Независимость |
|---|---|---|
| Game state | Ядро, ROM, состояние консоли, кадр, дата, превью | Загрузка не откатывает ΔW/Wexo/пороги/веса адаптера |
| Learned state | Граф/порты, ΔW, Wexo, пороги, состояние обучения, RNG | Не заменяет ROM или состояние игры |
| Training history | Эпизоды, происхождение награды, разделение train/control, оценки | Счётчики/журнал не доказывают приобретённое поведение |

Загрузка консоли очищает незавершённую временную привязку действия и награды,
но сохраняет приобретённые параметры. Перенос игры к прошлому кадру с продолжением
обучения — обязательный сценарий. Checkpoint сети и game state имеют разные форматы.

## Последовательность и ворота приёмки

| Этап | Проверяемый результат | Статус этой итерации |
|---|---|---|
| 1 / P0 | Независимость эмулятора, ошибки, pause/resume, ROM/reset, CPU/RAM/frame/audio/save baseline всех ядер | Исправлена изоляция ошибок, добавлены регрессии и инструмент baseline; host-прогон всех ядер выполнен, полная Android-матрица остаётся |
| 2 / P1 | Каталог game states, безопасное хранение learned state, роли Current/Best/Recovery | Каталог и поколения Current/Recovery/Best реализованы для single-agent; парное продвижение и защита прежней модели проверены на mechanism-фикстурах, игровая Android-приёмка открыта |
| 3 / P2 | Достоверная награда, несколько отрезков, independent frozen evaluation | Unknown обрабатывается безопасно; добавлены архив стартов, scheduler, native train/control, изолированный парный runner и guarded promotion; полноценный replay/игровые профили остаются |
| 4 / P3 | Игровая навигация, touch/back/controller/landscape, лаборатория отдельно | Существующее быстрое меню адаптировано к асинхронным снимкам; полный редизайн отложен до P0/P1 |
| 5 / P3 | Измеренная оптимизация CPU/GPU и релизная совместимость | Новые режимы не включались; релиз не объявлен |

## Выполненный первый срез

* `lab.js`: ошибки наблюдений, пластичности и neural bridge отделены от исключений
  ядра. Отключается агент, освобождаются его кнопки и устаревшие callbacks,
  сохраняется игра и доступ к ручному управлению. `labAgentStatus()` возвращает
  текущую связность и явный `failure` с контекстом. Быстрое меню показывает ошибку.
* `fdbOutcomeReward` и `fdb-feedback.js`: отсутствующая ручная оценка,
  неподтверждённый diagnostic ROM, отсутствующее подтверждение счёта и несовпавший
  контекст не отправляют `reward:0`. Отправляется подтверждаемая граница,
  очищающая eligibility; ошибка подтверждения блокирует новую причинную привязку.
  Явная ручная оценка и настроенные RAM-критерии остаются исследовательскими API.
* `save-states.js` / `state-ui.js`: quick, auto и шесть слотов для каждой
  платформы+ROM SHA256, версия ядра, SHA256 содержимого, дата и превью.
  Перезапись защищена подтверждением и ревизией; предыдущий валидный снимок
  остаётся резервным. Ошибка квоты не удаляет действующее сохранение.
  Перенос старого `platform-slot` требует проверки ROM и формата самим ядром;
  исходная запись сохраняется. Автоснимок делается при переключении системы/ROM
  и уходе в фон независимо от готовности графа. Каталог переживает перезагрузку.
* Нейронный backend отсутствует в browser-регрессии: проверяется реальный NES,
  а не поддельная модель игры. Native plasticity проверяется отдельным Java-тестом.
* `LayerSetStore.java`: native checkpoints хранят SHA256 и резервное поколение,
  совместимы со старыми raw JSON-файлами. Повреждённая основная запись
  восстанавливается из проверенного резерва с сохраняемым предупреждением;
  испорченные данные не заменяют валидный резерв. Проверяется отказ записи и
  квота. Лимит 32 МиБ теперь учитывает оба поколения и служебную упаковку,
  поэтому полезная ёмкость меньше прежней. Это защита хранения, не автоматический
  выбор доказанного Best и не доказательство сохранения навыков.

Game states хранятся в IndexedDB: основное и резервное поколения записываются
одной транзакцией с проверкой ревизии внутри неё. Старые localStorage-записи
читаются и переносятся при записи без удаления исходника. В Chromium проверены
все восемь слотов с настоящими снимками NES, rollback транзакции при отказе
записи и конкурирующие записи двух экземпляров. Квота WebView остаётся конечной;
отказ должен сохранять оба прежних поколения. В следующем срезе добавлены приватная библиотека ROM и автоматическое
повторное открытие последней игры выбранной платформы; battery-backed SRAM `.sav`
остаётся отдельной незавершённой возможностью. Устойчивость при аппаратном выключении и
доступная ёмкость конкретного Android WebView ещё требуют проверки.

## Углублённая проверка границ операций

* Native ошибки sample/configure/systemButtons привязаны к поколению запроса;
  устаревшая ошибка не должна отключать новую сессию. После отказа нейросети
  её маршрутизация и watchdog изолированы, ручная игра остаётся доступна.
* DualAgent также различает неизвестный исход и явный числовой ноль.
  Неоценённый отрезок очищает причинную привязку без обновления весов/baseline;
  frozen-оценка не получает скрытую команду изменения eligibility.
* Загрузка игры ждёт подтверждения dual boundary перед возвратом к прошлому
  кадру. Смена ROM или возобновление игры во время ожидания отменяют загрузку.
  Автоснимки сериализуются и захватывают состояние до асинхронной записи.

## P1: защищённые поколения моделей

Перед первым действием single-agent `ensureCurrent` сохраняет mutable Layer Set
и указатель продолжения независимо от опционального автосохранения. Native bind
создаёт защищённый checkpoint до ACK; ошибка записи отзывает разрешение на
обучение. Смена ROM, графа или конфигурации требует нового подтверждения.
Ручная игра остаётся доступной во время ожидания и после ошибки обучения.

`LearnedRoles` хранит полные immutable поколения по SHA256 отдельно от mutable
Layer Sets. Контекст — платформа, ROM SHA256 и граф SHA256. Порты и профиль входят
в полный snapshot: восстановление возвращает всю конфигурацию, а не переносит
дельты между несовместимыми конфигурациями. Manifest и резервный manifest
содержат Current, Recovery и `best: null`. Повтор идентичного checkpoint не
вытесняет Recovery. Сначала записывается поколение, затем атомарно заменяются
метаданные; fsync применяется к файлу. Устойчивость к внезапному отключению
питания на Android ещё требует проверки на устройстве.

Архив обновляется при native bind и успешном checkpoint интерфейса, а не на
каждом reward. Это защита сохранённого опыта, не обещание отсутствия потерь всех
последних шагов при аварии. Recovery означает предыдущую версию с проверяемой
целостностью; поведенческая безопасность этой версии пока не доказана.
Повреждение Recovery явно отображается даже при исправном Current.

При утрате UI-указателя продолжения используется архивный контекст. Более свежий
исправный mutable Current сохраняет приоритет. Если mutable-файлы повреждены,
проверенное поколение материализуется под новым UUID с постоянным уведомлением;
исходные повреждённые файлы остаются для диагностики. Если оба manifest непригодны,
восстановление завершается явной ошибкой и не удаляет поколения.

Ссылочные Current/Recovery защищены от ручного удаления Layer Set. Очистка
удаляет только поколения, на которые не ссылается ни один manifest. Архив имеет
отдельную квоту 32 МиБ и максимум 32 контекста; она добавляется к квоте mutable
хранилища. Переполнение явно блокирует новый checkpoint, сохраняя прежний.
Dual-agent продолжает использовать отдельное хранилище и не включён в эти роли.

Best остаётся неподтверждённым: продвижение требует независимых удержанных
стартов, проверки регресса и замороженной пластичности. Даже manifest с корректной
контрольной суммой и ненулевым Best сейчас отклоняется. Экспорт существующих
Layer Sets остаётся доступен в расширенном интерфейсе.

## P2: доказательное обучение между отрезками

История должна хранить `runId`, `episodeId`, `startStateId`, группу происхождения,
ROM/core/graph/ports/profile SHA, завершённость, вмешательства, источник и
достоверность награды, идентичность checkpoint до/после, назначение train/control.
Неизвестный исход хранится отдельным значением, не как успех, поражение или ноль.
Ограниченные журналы Layer Set/`trials` не являются такой базой эпизодов.
Следующий срез добавляет `EpisodeHistory` с durable метаданными и полными FDB
отпечатками. Текущий CurriculumStore добавляет native-разделение по происхождению;
replay ещё не реализован. Следующий срез добавил сохраняемую регистрацию пары, изолированную оценку и продвижение Best с retention; детали и ограничения приведены в новом отчёте.

Разделение выполняется по игровым стартам/независимым прохождениям до обучения.
Соседние кадры, повтор одного trajectory и пересекающиеся записи не являются
независимым контролем. Контрольные данные не используются для подбора маршрутизации,
награды или профиля; повторный подбор требует нового контрольного набора.

Frozen evaluation сравнивает Current и Best на одинаковых удержанных стартах и
seed, включая прежде освоенные отрезки. До/после сверяется полный канонический
checkpoint FDB: ΔW, Wexo, пороги, RNG, baseline, eligibility и счётчики, с отдельно
описанной семантикой разрешённого сброса временной фазы. Существующий benchmark
проверяет `weights_unchanged` только у внешнего адаптера; этого для promotion FDB
недостаточно. Сначала требуется расширить runner и тесты целостности проверки.

До запуска серии фиксируются минимальная выборка, основная метрика, допуск
регресса на старых отрезках, критерий улучшения с неопределённостью и правила
множественных сравнений. Краткосрочная награда сама по себе не заменяет этот
протокол. Если данных недостаточно, Current сохраняется, Best остаётся прежним.

Основной агент использует пластичность коннектома. SARSA, имитация и архивное
обучение внешнего readout остаются явно названными baseline. Существующий archive
replay не объявляется replay-обучением FDB. Новый scheduler не должен незаметно
подменять контроллер или учиться на ручных нажатиях как на положительной награде.

## Рамки A/B/A2/A3

Основание — [зафиксированный handoff](FDB_RESEARCH_HANDOFF_AB_A2_A3_RU.md).
Сначала исследуется существующая маршрутизация сенсорных/моторных портов.
Расширение количества параметров, динамических кандидатов и пороговой пластичности
не считается улучшением по умолчанию. При перераспределении кандидатов нужно
сохранять приобретённые ΔW/Wexo и совместимость checkpoint.

Результаты получены на 30–90-нейронных фикстурах. A3 заменяет confounded вывод A2;
feedforward-эффект не доказывает recurrent memory. Задержанные оболочки задачи
не считаются независимыми подтверждениями. Перенос на FlyWire/Male CNS,
вычислительная экономия и производительность устройства не установлены.
Недостижимость `FdbGrowth` в DualAgent не исправляется автоматическим включением
одновременной мутации: сначала нужен отдельный контракт взаимодействия механизмов.

## Проверка и измерения

Из корня checkout после активации JDK/Python/Gradle:

```sh
bash tools/check.sh
CHROMIUM_EXECUTABLE=/usr/bin/chromium NODE_PATH=/path/to/node_modules node tools/autonomous_console_ui_check.cjs
GU_BASELINE_FRAMES=18000 node --expose-gc tools/emulator_baseline.cjs /tmp/emulator-baseline.json
gradle --no-daemon assembleDebug lintDebug
```

CI сначала генерирует ядра: Emscripten 3.1.57, `tools/build_sega.py`,
`tools/build_retro.py`, `tools/make_retro_roms.py`. Sega WASM обновлён до API6 из закреплённых исходников; GB/SNES собраны
тем же Emscripten. Полный host-прогон прошёл после генерации всех ядер. Для диагностирования отдельной
платформы можно явно задать `GU_BASELINE_SYSTEMS=nes`; это не проверка остальных.

Baseline фиксирует host frame-time p50/p95/p99/max, unpaced throughput, process CPU,
RAM/heap samples, save/load и детерминизм после восстановления. Audio samples
подтверждают транспорт, не синхронизацию с Android AudioTrack/WebAudio.
Периодический GC включён в wall time. Нейронная latency, GPU и батарея остаются
`null`, если не измерены; никакие FPS хоста не выдаются за телефонные FPS.

Для релиза обязательны реальные Android pause/background/resume, Back,
touch/controller, landscape, аудиосинхронизация, длительная память, энергопотребление
и восстановление после ошибок. Каждая непроверенная клетка остаётся открытой.
