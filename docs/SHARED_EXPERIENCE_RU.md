# Общий опыт и аудит FDB — 2.1.0

## Реализовано

Используется существующий CPU/GPU движок и неизменяемый граф W₀. Новый каталог хранит небольшие снимки приобретённых параметров, а не копии коннектома:

- ROOT: общие ΔW, Wexo и смещения порогов.
- Жанр: разница относительно конкретного SHA ROOT, включая отрицательные поправки и удаление ранее приобретённых связей.
- Игра: отдельная обучаемая копия суммы ROOT и жанра. Полное эффективное состояние сохраняется обычным Layer Set; привязка содержит неизменяемые исходные снимки. Экспорт игровой разницы вычисляет остаток относительно этой базы.
- Индивидуальный снимок допускается только для своего ROM.

Обучение изменяет только игровую копию. Каталог не обновляется автоматически. Консолидация создаёт нового кандидата с новым SHA. Изменённый ROOT нельзя незаметно подставить под старый жанр. При выборе новой копии сначала сохраняется текущий опыт; затем отвязывается старый Layer Set, очищаются временные следы, сбрасывается динамика сети, игра остаётся на паузе.

## Как использовать

1. Импортировать `examples/synthetic/01-simple.json`, `02-medium.json` или `03-complex.json` через импорт JSON. Это топологии, не предобученные навыки. Выбрать ROM и настроить порты, действия и награду.
2. Обучить игру существующим FDB, затем в «Общий опыт · ROOT / жанр / игра» сохранить кандидата ROOT.
3. В другой игре с тем же графом и совместимым контрактом выбрать ROOT, разрешить экспериментальное использование кандидата и создать новую игровую копию. Сохранить новый Layer Set.
4. После обучения сохранить кандидата жанра. Он ссылается на активный ROOT; исходные игры записываются в происхождение слоя.
5. На третьей, не использованной для создания слоя игре сравнить чистый W₀ с ROOT + жанром. Кандидаты остаются экспериментальными до проверки отчёта.
6. Экспортировать общий слой отдельным JSON. На другом устройстве импортировать ROOT и жанр отдельно. Существующие игровые Layer Sets импортируются своим прежним механизмом.

## Контракт совместимости

Проверяются SHA графа, строковые 64-битные ID и порядок 16 входов и 8/12 выходов, семантические названия кнопок, допустимые маски и набор действий, версия сенсорики и нейродинамики, частота входа, gain, окно и порог чтения, CPU/GPU и настройки удержания кнопок. Перенос с отключённой сенсорикой, перемешиванием, отключением торможения или поражениями запрещён.

Сенсорика остаётся сеткой яркости 4×4. Названия выходов описывают совместимость: они **не** переставляют физические кнопки и **не** распознают здоровье, угрозы или положение персонажа. Межплатформенный перенос по умолчанию разделён именами выходов. Совпадение контракта не доказывает полезность переноса.

## Проверка кандидата

Отчёт содержит `version:1`, `candidateDigest`, `metric`, `direction` (`higher`/`lower`) и `pairs`. Каждая пара содержит `romHash`, `seed`, `episodes`, `trainingSteps`, `control`, `transfer`, `controlCostMs`, `transferCostMs`, `protocolSha`.

Требуются минимум три различных seed, отсутствие ROM проверки в `sourceRoms`, уникальность ROM/seed, одинаковый протокол и бюджет для seed одной игры, конечные числовые результаты и положительное среднее улучшение. Протокол должен фиксировать версию приложения, адаптер и награду, стартовый снимок, бюджет, процедуру оценки без обучения и порядок запусков. Для каждого seed контроль и перенос запускаются с одинаковым бюджетом из независимых динамических состояний. Нельзя выбирать только удачные seed. Проверять также отрицательный перенос на других играх и разброс результатов.

Статус `validated` означает, что предоставленный отчёт прошёл эти формальные проверки. Приложение не удостоверяет происхождение внешних измерений и не рассчитывает статистическую значимость. Изменение отчёта/кандидата обнаруживается digest. Автоматический запуск сравнительных опытов на произвольных коммерческих ROM пока отсутствует.

## Закрытые дефекты аудита

| Дефект | Исправление / проверка |
| --- | --- |
| Диагностика могла показывать глобальную последнюю модель вместо графа конкретного контура | GraphCache.identity(graph), отдельная идентичность объекта; тест переключения моделей |
| Выбор модели и загрузка портов могли читать разные моменты выбора | Один captured model ID на загрузку |
| Попадание в текущий слот кэша обходило ожидаемый SHA | Проверка SHA при попадании в кэш |
| JSON топологии попадал в импорт игрового набора | Отдельный тип `fly-synthetic-graph`, строгий CSR-парсер и content-addressed файл |
| Повторные записи ΔW могли складываться при восстановлении | Общий строгий restoreLinks для одиночного и двойного режима |
| Wexo мог дублировать ребро W₀ | Проверка класса связи: ΔW только существующие, Wexo только новые |
| Checkpoint обучения проверял порты, но не всегда сам граф | Новый checkpoint сохраняет SHA графа; несовпадение отвергается до изменения learner |
| Расширенный отбор 16 связей удалял индекс 8 вместо самой слабой связи | Отбор сильнейших 16; checkpoint помечает версию проекции. Точное совпадение со старым алгоритмом мигрирует веса и счётчики, сбрасывая устаревшие eligibility и нейронные следы. Неизвестная проекция отклоняется |
| `learning:null` приводил к случайной JS ошибке | Явная проверка объекта и понятная ошибка |
| Общий опыт мог проверяться по текущему экрану при загрузке другого сохранённого профиля | Проверка импортируемого профиля до восстановления, затем проверка фактических действий при запуске |
| Изменение общего опыта могло затронуть прежний игровой набор | Неизменяемый каталог и явное отсоединение старого набора перед созданием копии |

Старые checkpoint без внутреннего SHA сохраняют совместимость, но должны загружаться внутри проверенного FDB/Layer Set с идентичностью графа. Имена файлов FlyWire и Male CNS разные; совпадение их путей аудитом не обнаружено.

## Проверки и границы вывода

Локально пройдены проверки SHA-256 (включая Unicode и длинную строку), композиции/вычитания слоёв, идентичности графов/портов/действий/бэкенда, сохранения при отказе хранилища, запрета подмены родителя, отчётов переноса, восстановления UI и смены ROM. Java-проверки покрывают checkpoint, динамику порогов, пять режимов пластичности, рост/удаление связей, неизменяемость W₀, заморозку, отложенное подкрепление, P1/P2, числовую точность больших ID и продолжение обучения.

Это проверки механизмов. Малый fixture с большими ID не является Male CNS. Полные FlyWire и Male CNS проверяются CI через `check_full_dual.sh` после загрузки данных, отдельно в обычном и expanded режимах. Проверка настоящего переноса игрового навыка требует сравнительных запусков на ROM; такого результата эта версия не заявляет.

Ограничения: общий каталог доступен в одиночном контуре; P1/P2 сохраняют отдельный прежний механизм. Нет автоматической семантической адаптации RAM между играми, автоматического слияния жанров и выборочной активации вычислительных ветвей. Тормозные/модуляторные допущения исходных биологических моделей не исправляются произвольной сменой весов. Каталог ограничен 32 версиями / 4 МиБ, слой — 2048 записями каждого класса. При превышении лимита операция отклоняется без усечения.
